The Market Engine v6 already does several things well: it has a serious quantitative backbone (multi-scenario Monte Carlo, crash probability outputs, and a broad feature surface across macro, volatility, and sentiment), it exposes these capabilities through a practical API surface, and it attempts to unify regime detection and macro validation with dedicated services rather than burying everything inside one script. The project also demonstrates a healthy architectural intent: there is a scheduler, persistent storage, a dedicated regime service, and dedicated data services for macro/fred logic. Those are all strong foundations for an institutional-style system rather than a hobby-only predictor.

The primary failures are not a lack of models but inconsistency between modules and data semantics. The most critical bug is macro unit integrity: the data pipeline has been capable of storing raw CPI index values as if they were rates, which can create front-end misinformation and contaminate downstream regime/risk logic. A second high-impact issue is market-state fragmentation: one part of the system computes a centralized HMM-style state while another path can still persist regime records from separate logic, producing contradictory "truths" across pages. A third operational issue is heavy compute on demand from user-facing endpoints in ways that can degrade page performance and create perceived instability. The net effect is that sophisticated components exist, but confidence is reduced by mismatched definitions, stale/duplicated pipelines, and inconsistent consumption of the single-source-of-truth design.

Phase 1 should be an accuracy-and-consistency stabilization sprint focused on correctness over new features. In `backend/data_fetchers.py`, keep macro ingestion but treat CPI as a transformed rate (YoY percent) before persistence, and explicitly retain unemployment as percentage-level data rather than applying a percent-change transform. In the same file, eliminate local regime determination and always source regime/confidence from the centralized market-state service so scheduled updates and API reads use the same state model. In `backend/main.py`, enforce this same policy by treating `/api/market-status` as canonical for regime values and de-emphasizing legacy endpoints that return partially overlapping interpretations. In `backend/services/fred_data_service.py`, retain threshold validation and ensure fallback behavior is explicit when validation fails, so the UI receives an interpretable warning state rather than silently mixing defaults with live data. In `frontend/src/pages/*` views that still call legacy endpoints, migrate their regime/macro cards to the unified endpoint contracts and align label semantics (index vs rate, level vs spread) to stop contradictory dashboard narratives.

Phase 1 should also include computational reliability hardening. In `backend/main.py` and `backend/scheduler.py`, move expensive Monte Carlo requests to precomputation windows with result caching and TTL checks, then serve the latest validated snapshot to interactive views. In `backend/services/monte_carlo_service.py` and `backend/engine.py`, preserve geometric/log-return dynamics and hard guardrails, but centralize the caps and outlier flags in one config path so every endpoint uses the same constraints and explanation text. Add lightweight regression checks that fail fast for known historical bugs: CPI displayed as a three-digit percentage, inconsistent regime between `/api/market-status` and persisted `MarketRegime`, and unrealistic 5Y projections beyond cap without anomaly flags.

Phase 2 should then expand intelligence once trust is restored. Introduce historical-memory news intelligence via vector retrieval and narrative comparison so predictions explain "why now" with analog events. Add market microstructure and liquidity context (net liquidity, skew metrics like VVIX/put-call) and expose their contribution weights to users. Build walk-forward evaluation as a first-class product artifact from 2000 onward and track calibration drift over time, not just static error metrics. Finally, make explainability mandatory: every crash probability and price cone should disclose top drivers, uncertainty band quality, and whether the result passed or failed sanity gates. The strategic principle is simple: first enforce one truth with validated units and synchronized state, then scale to richer signals and institutional-style diagnostics.
